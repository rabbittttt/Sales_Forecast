## 浏览器性能实测与逐项优化：2026-10-02

### 结论及范围

本轮最严重的已确认瓶颈是**销量预测页面的同步初始化**：进入/返回页面时，主线程集中执行参考推荐、尚未打开的打分说明、图表与DOM生成，并反复进行数字格式化。基线进入预测的单次最长任务中位数827ms，明显超过50ms长任务阈值；底表搜索约51ms，不是本地样例中的首要瓶颈。

以 `ce6046f` 为基线，逐项修改、运行正式main、立即验证，再决定保留。最终仅保留两项：复用数字格式器；首销打分说明按需生成。第三项日历特征复用因收益不明确撤回。预测公式、推荐权重、阶段取数优先级、实际订单、可选参考、图表数据点及周期均未减少或改变。最终进入预测快18%、返回预测快33%、新页面直接打开预测快23%；**不是全站提速，也未证实内存下降**。

### 测量方法

- 设备：Windows，Intel i5-8265U，8个逻辑线程，可见物理内存8038MiB；Edge 154.0.4258.48，1440×1000，headless、Asia/Shanghai、减少动态效果。使用正式 `output_file/鸿蒙智行订单分析汇总.html`，32个主体、152个看板、约4.4MB；预测对象为本机已有的问界M9 2026款。
- 基线、每个单项实验、最终版本各5轮，另有2次CPU采样用于定位，不计入基准；共25轮主测量。每轮启动独立浏览器和空本机存储，顺序一致，不与本任务的生成、单元测试、其他浏览器测试并行。没有独占整机，也没有清除操作系统文件缓存，不能当作严格冷磁盘测试或线上用户分位数。
- 响应耗时：自动化指令发出，直到对应状态完成且经过两次 `requestAnimationFrame`。包含自动化调度开销，不是标准INP；首次打开总览不含浏览器进程启动，新页面直接打开预测使用已启动浏览器内的独立页面/上下文。
- CPU时间：CDP `SystemInfo.getProcessInfo` 中**受控Edge的全部进程**CPU秒数差值，含浏览器、渲染、GPU等，不含其他应用。平均CPU占用率=CPU时间÷响应时间÷8，不是瞬时峰值。主线程时间与长任务分别来自 `Performance.getMetrics` 和 Long Tasks API。各列分别取5轮中位数，因此中位CPU时间/中位耗时不必恰好等于中位占用率。
- 内存：操作后用Windows `Get-Process` 采样受控Edge进程的工作集和私有提交量；工作集求和可能重复包含共享页，私有提交量也不等于实际驻留RAM。另记录JS堆及主动GC后的保留量。**这些是操作后快照，不是连续峰值或内存泄漏证明。**
- 所有样本保留，包括慢样本；未剔除异常值。最终5轮“进入预测”范围715–1838ms，总览首次打开422–2141ms，故小幅变化不能据此判定为稳定收益。HTML哈希写入报告，并检查测量过程中正式文件未被其他生成任务替换。
