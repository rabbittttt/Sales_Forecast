# 销量预测

持久目录统一为同级工作区的 `工作台数据/database/forecast/`；独立运行与门户运行读取同一位置。可用 `PLANHUB_DATA_ROOT` 指定数据根（相对路径按应用根解析），应用原有显式数据目录参数继续优先。程序发布不携带业务数据库；发布版使用 `planhub-runtime/database/forecast/`。共享 Excel 仍在原共享目录，数据库集中不改变业务口径。首次升级必须停服迁移，旧目录改名为 `.pre-central-*` 恢复备份，不再参与运行。

公共代码仓库：[rabbittttt/Sales_Forecast](https://github.com/rabbittttt/Sales_Forecast)。

本目录是独立项目。代码、模板、配置、预测算法、测试、浏览器草稿、网页资源和日志均由本项目独立维护，不导入或调用“订单分析”的代码。销量数据汇总由本项目更新到共享目录，供各项目读取。

## 运行

静态网页与动态网页分别启动，输出也分别保存：

```text
销量预测/
├─ 运行静态销量预测.bat
├─ 运行动态销量预测.bat
├─ static/
│  └─ main.py
├─ dynamic/
│  └─ serve.py
├─ output_file/
│  └─ static/
│     ├─ 鸿蒙智行销量预测.html
│     └─ log/
├─ main.py                        （兼容静态入口）
└─ serve.py                       （兼容动态入口）
```

所有项目默认共用所在 `Project/.venv`。新电脑先安装 Python 3.11 或更新版本（共享环境要求，独立启动脚本的版本检查下限为 Python 3.10），在 `Project` 根目录双击“初始化共享环境.cmd”重建共享环境并安装依赖。也可在本项目根目录手动安装：

```powershell
..\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

启动脚本从项目根目录向上找到最近名为 `Project` 的目录，使用其中 `.venv\Scripts\python.exe`。可用 `SALES_FORECAST_PYTHON` 指定其他解释器文件，相对路径始终按本项目根目录解析。启动窗口显示所选 Python，环境缺失或依赖不全时停止并提示处理命令。

换电脑后应重新创建 `Project/.venv`，不要直接复制旧电脑的虚拟环境。整体移动 `Project` 时保留项目与共享目录的相对位置，上级目录和盘符可以不同。

### 静态网页

双击根目录的 `运行静态销量预测.bat`，生成并打开 `output_file/static/鸿蒙智行销量预测.html`。生成后可直接打开该 HTML，无需保持启动窗口运行，下次手动运行时更新数据。日志位于 `output_file/static/log/`。

在项目根目录运行命令，只生成文件、不打开浏览器：

```powershell
..\.venv\Scripts\python.exe static/main.py --no-open
```

### 动态网页

双击根目录的 `运行动态销量预测.bat`，启动本地服务并打开浏览器，默认地址为 `http://127.0.0.1:8780/`。动态结果位于 `../工作台数据/database/forecast/dynamic/`，日志位于 `../工作台数据/logs/forecast/`。

动态服务中的外部逐日预测按车型共享，访问同一服务的用户都能看到导入、清除和撤销后的数据。导入原文件在浏览器解析，仅将选中车型的预测行存入服务数据目录；静态文件和旧版浏览器导入仍保存在本机。负数不接受，小数按原值保存，日值及合计在显示时分别四舍五入。

后台服务每 300 秒检查共享原始输入，发现变化后，等待文件连续稳定 60 秒再更新预测。浏览器在页面可见时每 15 秒检查页面版本，发现新版本后自动刷新。重启时先展示同一输入目录上次成功生成的页面，并提示“后台数据刷新中”。同版本的输入、配置、业务日期和共享汇总核验通过时，直接恢复并撤下提示。没有历史页面时显示生成状态。后台检查共享汇总，有效时直接生成当前版本的页面，跳过等待和 Excel 重算。汇总过期、缺失或损坏时，等待输入连续稳定 60 秒再重算。更新失败时保留上次成功页面、显示失败状态并自动重试。使用期间保持服务窗口打开，按 `Ctrl+C` 停止服务。同一版本重复启动会打开已有服务。更新程序后，先在原服务窗口按 `Ctrl+C` 并等待退出，再重新运行动态启动脚本。

在项目根目录手动启动：

```powershell
..\.venv\Scripts\python.exe dynamic/serve.py
..\.venv\Scripts\python.exe dynamic/serve.py --host 127.0.0.1 --port 8780 --no-open
```

`--no-open` 只关闭自动打开浏览器。动态地址与直接打开静态文件的浏览器人工参数各自保存。

两个启动 bat 均放在项目根目录。根目录的 `main.py`、`serve.py` 分别提供静态和动态命令行入口。默认输入、输出路径以项目根目录解析。

## 门户接入与发布

门户仍访问 `/forecast/`，独立运行仍访问 `/`。原项目启动示例：

```powershell
..\.venv\Scripts\python.exe -B dynamic/serve.py --no-open --public-prefix /forecast/
..\.venv\Scripts\python.exe -B scripts/build_release.py --version 2026.11.11.1 --destination output_file/releases/forecast-2026.11.11.1
```

标准包只有 `app-release.json` 和 `payload/`，包含同版代码、模板、资源与 requirements.txt，不带 Excel、日志、缓存或浏览器草稿。发布目录不可覆盖，前后端一起切换。部署电脑安装依赖后运行包内 `dynamic/serve.py`：

- `--host 127.0.0.1 --port 8780 --no-open --public-prefix /forecast/`；代理整段前缀，支持剥除或保留前缀，页面可同源嵌入。
- `--data-dir` 或 `SALES_FORECAST_DATA_DIR` 指定版本目录外的运行根；相对值按项目（发布时为 payload）根解析，正式部署传绝对路径。动态页面、资源、锁和缓存写入该目录。工作台提供 `PLANHUB_APP_LOG_DIR` 指向包外 `logs/forecast/`；独立部署使用标准 `database/forecast/` 布局时也会定位同一日志目录。未配置时使用同级 `工作台数据/database/forecast`。
- `SHARED_DATA_ROOT` 显式指向部署电脑的共享根。保留原预测规则：只读原始输入，仅更新订单汇总中的销量汇总派生文件。账号须能写入该派生文件。
- `/healthz` 为轻量进程探针，返回 ok/app/ready/state。`/readyz` 在没有可展示页面或更新错误时返回 503。`/api/status` 给出更新状态和是否正在提供上次生成结果。没有已有页面时，入口显示生成状态并自动重试。

服务包、页面与共享汇总分别校验。未参加页面生成的服务代码改变时可直接恢复有效页面；页面模板变化时先展示上次结果，有效的共享汇总可直接用于生成新版页面。输入、业务日期或汇总计算依赖变化时重新校验汇总。动态网页的「详情」可查看并复制刷新原因、当前显示批次、目标页面版本和最近生成成功时间。同源门户隐藏预测页面后暂停前台轮询，重新展示时检查最新状态。发布前停掉旧服务，再切换版本；不要让新旧服务同时写共享汇总。浏览器人工参数仍由原页面维护，门户公共地址不变时继续沿用。

动态服务首次确认当前页面可用时，按输入目录保留当前页面和最近两个校验通过的历史版本。仍在运行的版本、含其他文件的目录，以及升级前未登记使用状态的离线缓存继续保留，以便旧服务和旧页面回退。服务启动日志列出实际采用的订单、参考和车型资料目录、共享汇总、动态页面、导入数据库、刷新缓存与日志文件。网页读取缓存的临时路径在每次生成时记录。

## 输入与输出

下表以源码项目根目录为基准。默认工作台数据根为 `../工作台数据`，可通过 `PLANHUB_DATA_ROOT` 覆盖。路径解析集中在 [core/data_paths.py](scripts/generate_html/core/data_paths.py)。

| 用途 | 默认位置 | 覆盖方式 |
| --- | --- | --- |
| 订单 Excel | `../工作台数据/shared/订单汇总/` | `SHARED_DATA_ROOT` 指定共享根，生成器的 `--input` 指定本次订单输入目录 |
| 小订与首销 | `../工作台数据/database/vehicle-config/campaigns/campaigns.sqlite3` | 只读车型配置中已发布的数据。首次使用前在车型配置完成发布。设置 `PLANHUB_DATA_ROOT` 可更换数据根，`VEHICLE_CONFIG_CAMPAIGN_DB` 可直接指定数据库路径。历史重放可用 `--source` 指定工作簿或已发布 JSON，或用 `VEHICLE_CONFIG_CAMPAIGN_SNAPSHOT` 指定快照。生成器的 `--input` 只切换订单输入 |
| 车型资料 | `../工作台数据/shared/车型信息/` | 跟随共享根，已维护的车型属性优先取整理表 |
| 派生销量汇总 | `../工作台数据/shared/订单汇总/鸿蒙智行销量数据汇总.xlsx` | 跟随共享根，独立刷新工具支持 `--output` |
| 静态 HTML 与日志 | `output_file/static/鸿蒙智行销量预测.html`、同级 `log/` | 生成器 `--output`、`--log-dir` |
| 动态结果、启动检查点、共享外部导入 | `../工作台数据/database/forecast/dynamic/` | `--data-dir` 或 `SALES_FORECAST_DATA_DIR` 指定预测持久根 |
| 动态日志 | `../工作台数据/logs/forecast/` | `PLANHUB_APP_LOG_DIR` |
| 网页读取缓存、汇总刷新缓存 | HTML 输出目录下的 `.cache/excel/`、预测持久根下的 `.cache/excel/` | 各自跟随输出目录或持久根，生成结束时清理 |

默认整理表文件名缺失时，生成器在同目录筛选含“小订”或“首销”的工作簿，优先含“数据整理”的文件；临时文件、副本、修正前版本、订单报表、映射与二次处理文件均排除。只采用筛选后的唯一候选，并在日志记录文件名；无候选或存在多个候选时报告错误。

共享目录中的原始工作簿只读。生成器只向共享目录发布上述派生销量汇总。已发布的汇总可由其他项目读取。整理表和订单输入缺失时，页面诊断会报告具体来源。当前静态预测页面可单文件打开；旧版离线页面若仍在使用，应与自己的资源目录一同保留。

## 盘中预测

小订与首销在有有效小时明细时，使用已采集小时的累计订单和参考完成进度推算全天；首日采用分时拟合。日表和小时表有交叠时，以已知实绩为下限，同一批订单只计算一次。仅有日表的非首日继续按日曲线分配，未发布的数据保留为空；已结束日明确填入的零继续作为实绩。平销以交车锁单计量，目前读取逐日锁单资料，当天实绩作为下限。

## 维护

在项目根目录运行 `..\.venv\Scripts\python.exe scripts/asset_index.py`，可刷新本机的 `output_file/maintenance/资产索引.html`，按关键词检索文件、用途、最后更新时间和仓内引用。索引与本机归档均放在 Git 忽略的输出目录；目录外的离线网页是否引用了某份资源，需按交付记录核实。

配置：`scripts/generate_html/config.json`。
算法：`scripts/generate_html/modules/sales_forecast.py`。
刷新汇总：`scripts/generate_html/tools/refresh_sales_forecast_data.py`。
页面：`scripts/generate_html/templates/`。
汇总代际的新旧名称对应关系统一维护在 `scripts/generate_html/core/model_identity.py` 的 `AGGREGATE_GENERATIONS`：`问界 M9&M9U 2026款`、`尊界 V680&V800 2026款`、`尚界 Z7&Z7T 2026款`、`享界 S9&S9T 2026款` 不再依赖“汇总”后缀识别。四组旧汇总代号与新名称可以在输入中混用，整理表决定预测显示名称；整理表中明确维护且名称无旧汇总后缀的预测对象继续参与取数，未维护的派生聚合继续排除。同一观察量沿用首个非空值，不重复累加，也不将单个成员车型视为聚合别名。新增组合须显式配置，程序不会仅凭 `&` 推断合并关系。
所有依赖为实文件副本，没有符号链接或对另一个项目的运行时引用；模块注册只包含销量预测。保留的通用实现和历史业务测试也是本项目自己的副本。

历史业务口径与分主题说明见[原预测功能说明](docs/原预测功能说明.md#阅读目录)，历次迁移与验收见[历史审计记录](docs/历史审计记录.md)。保留的订单分析回归夹具位于 `scripts/generate_html/tests/legacy_order/`，用于验证历史公共取数行为。

浏览器测试生成 Python 夹具时也默认使用所在 `Project/.venv`；既有 `PYTHON_EXE`、`PYTHON_BINARY` 可显式覆盖。带目录的相对值按本项目根目录解析，显式命令名保持兼容。

### 参考车型评分审查（2026-11-17）

- 直接大定占比：小订规模权重从 6% 调整为 16%。历史终值可用性仍是自动推荐资格，不再作为相似度加 10% 的固定分。规模相似度为两车总小订较小值除以较大值。
- 当前小订期未结束（包括结束当天）：仅使用同车型、同评估日期且无错误的小订预测终值参与规模比较；没有有效预测终值时跳过规模项，不把阶段累计量当最终规模。小订结束后沿用实际/维护总量。
- 转化率、直接占比和锁单参数：首销 D1 完整观测尚未形成时，使用阶段可获得的评分项计算覆盖率。缺少小订终值本身不排除参考，其他证据仍需达到有效权重门槛，历史输出指标仍须有效。
- 未知、缺失、横杠属性不作为匹配证据。平销锁单率相似度接受真实 0，排除空值、负数和超过 100% 的比例。

本轮核对范围与后续校准方向：

| 评分任务 | 当前审查结论 |
| --- | --- |
| 小订日节奏 | 属性、时长、规模共同评分；进行中累计量与历史终值的规模比较仍值得改为同进度比较，需单独验证预测联动。 |
| 小订及首销分时 | 比较共同已观测窗口内的小时形状与进度，发布时间可用于初选；不加入绝对小时销量。 |
| 首销小转大/直接大定进度 | 只比较已发生结构和曲线；D1/D2与累计形状存在相关性，后续应通过逐车型留出检验重复加权影响。 |
| 最终转化率/直接占比/锁单参数 | 本轮修正阶段覆盖和小订规模处理；参考终值有效性仍独立检查。 |
| 到天分配/每日斜率 | 保留完整曲线资格及真实日、日历还原边界；缺失曲线的固定分仍可在后续统一改成资格展示。 |
| 首销量级 | 保留属性、首销天数与小订规模；共用修正后的未结束小订取数。 |
| 平销承接 | 保留首销归一形状和同龄完整周趋势为主的权重，修正锁单率零值边界。 |

以上是规则修正，16% 并非历史误差拟合出的最优权重。后续校准应按历史预测时点重建当时可见数据，用逐车型留出比较预测误差与简单基准，避免拿终局信息参与当时评分。
